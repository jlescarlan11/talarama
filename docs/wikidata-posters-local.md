# Local Wikidata poster support

The owner requested real posters while preserving the restored UI, functional improvements, existing IDs and member data. Work extends the existing artwork path on the local branch; it requires no schema migration, backfill, member update, credential, push or deploy. Source licensing remains pending. Existing TMDB artwork and records are retained.

Wikidata's [film poster property P3383](https://www.wikidata.org/wiki/Property:P3383) supplies Commons file identities. P18 is also considered when the filename or Commons categories identify a poster; arbitrary cast photographs and stills are not substituted. The [Commons imageinfo API](https://www.mediawiki.org/wiki/API:Imageinfo) supplies the thumbnail and per-file metadata. Accept only portrait JPEG/PNG/WebP images marked public domain or CC0 with attribution explicitly not required; reject unknown/nonfree licenses, restrictions, deletion nominations and missing metadata. These are provider assertions, not a new legal clearance or public-release approval. Recent copyrighted posters commonly remain unavailable through this route.

Requests target the fixed Commons HTTPS API, batch at most48 candidate files, reject redirects, time out after8seconds and bound bodies to2MiB.429 applies a separate60–3600second Commons cooldown. Thumbnails and source pages must have approved HTTPS hosts/paths and match the requested Commons filename. Tracking queries are removed. Metadata text is rendered as escaped plain text. No title matching, scraping of nonfree Wikipedia posters, arbitrary media proxy or remote member-state transmission is introduced.

The existing Next Image components render Commons' pre-sized thumbnails directly with no referrer. Catalog, carousel, detail, diary card, diary modal and log-preview paths retain their layouts and support the imported poster. Narrow image host patterns also permit the Commons paths. Existing missing/broken-image behavior remains. Movie details show the source file, artist, credit and public-domain/CC0 declaration without restyling the page.

On explicit authenticated import, new movie snapshots include poster URL and provenance in the existing credits JSON. Existing mapped movies are returned unchanged. Malformed or mismatched saved poster credits are discarded independently from valid saved cast/directors. No existing Movie ID or member relationship changes. Reads never import records.

Wikidata metadata and Commons responses have separate bounded/coalescing process caches. Artwork decoration happens after metadata cache reads; failed Commons requests are not retained. There is no outer Next cache of a decorated posterless success. This allows another request after a transient image outage or cooldown to recover the poster without refetching Wikidata metadata. Starting a fresh preview/test process isolates caches without a persisted fixture payload.

One independent review found diary renderer compatibility, artwork recovery and saved-credit isolation issues. Each was reproduced with a failing regression and fixed. Same-host wrong-file metadata was additionally rejected with a RED→GREEN test. A browser compile caught a Windows text-encoding error in the new caption; the caption was corrected and changed sources were checked as UTF-8.

Direct public reads returned a real Commons poster for **12 Angry Men (1957), Q2345**, in both discovery and detail. Inception remained a fallback; its Wikidata image is a cast photo. This demonstrates the coverage boundary. Local test/build/browser evidence and screenshots are recorded at completion below; fixtures are always separate from live-provider evidence.
